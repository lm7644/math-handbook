数值计算与稳定性

BF16、梯度累积，为什么训练会炸

数学课本里 softmax 永远良定义，可到了计算机里，logits 一大就直接炸成 NaN——因为机器里的「实数」是有限的、有缝的。本章讲清有限精度浮点引发的三类事故（上溢、下溢、病态），以及工程上的标准解法：log-sum-exp 技巧、混合精度训练、损失缩放、梯度裁剪，最后给一份「训练炸了」的排查清单。每个技巧都会亲手算一遍、用 python3 核一遍。学完你就明白：loss 曲线上每一个尖峰都有数值根源，没有灵异事件。

7.1 浮点数：有限的格子记无限的实数

直觉 · 先建立感觉

浮点数 = 用有限的格子记无限的实数，格子有大有小。实数轴上有无穷多个数，而一块芯片用固定的 32 位或 16 位二进制来记账——位数有限，能摆下的「格子」就有限，每个实数只能四舍五入到最近的格子。格子还不是均匀铺的：靠近 0 的地方格子密（能分清 \(1.000001\) 与 \(1.000002\)），远离 0 的地方格子稀（\(10^{20}\) 与 \(10^{20}+10^{13}\) 落在同一格）。此外格子还有边界：太大的数直接「记不下」（上溢成 inf），太小的数被「抹成 0」（下溢）。本章所有事故，都是「格子太稀」或「越过格子边界」引发的。

IEEE 754 浮点标准把一个数拆成三部分记账：1 位符号 \(s\)、若干位指数 \(e\)、若干位尾数 \(f\)，

\[ x=(-1)^{s}\times 2^{\,e-\mathrm{bias}}\times 1.f \tag{7.1} \]

读一下这个式子：符号位管正负；指数决定格子的「量级」——指数位越多，能表示的最大数、最小数离 0 越远，也就是范围越宽；尾数决定格子的「密度」——尾数位越多，同一量级内相邻两格的距离越小，也就是精度越高。位数总共就那么多，范围与精度此消彼长，不同格式就是不同的分配方案：

格式总位数（符号/指数/尾数）最大正数相对精度深度学习中的角色
FP3232（1/8/23）\(\approx 3.4\times10^{38}\)\(2^{-24}\approx 6\times10^{-8}\)主权重、优化器状态、累加器
FP1616（1/5/10）\(65504\)\(2^{-11}\approx 5\times10^{-4}\)早期混合精度训练、推理
BF1616（1/8/7）\(\approx 3.4\times10^{38}\)\(2^{-8}\approx 4\times10^{-3}\)LLM 训练前向/反向的默认格式

（三个相对精度与 FP16 最大值均已用 python3 验算：\(2^{-24}=5.96\times10^{-8}\)，\(2^{-11}=4.88\times10^{-4}\)，\(2^{-8}=3.91\times10^{-3}\)。）

盯住 BF16 这一行，它是一次极有意识的取舍：指数保留与 FP32 相同的 8 位（范围一样宽），尾数砍到只剩 7 位（精度只有约 2–3 位十进制有效数字）。为什么这笔买卖划算？因为深度学习的前向、反向计算有个特点：对「糙」容忍、对「炸」零容忍。逐元素的舍入噪声在大量累加中相互抵消（7 位尾数够了），但一次上溢就是 inf 再变 NaN，全盘皆输（所以范围必须与 FP32 同宽）。FP16 正好相反：精但窄，最大才 65504，稍大的激活值就越界。

一句话对照：FP16 精但窄，BF16 糙但宽。训练怕「炸」不怕「糙」，所以 BF16 胜出。
例 7.1 · 动手算

题目　感受 BF16 的「糙」：某参数值为 \(1.0\)，Adam 给它的一步更新量是 \(-0.001\)。若直接在 BF16 里做 \(1.0-0.001\)，结果是多少？

解　先算 BF16 在 \(1.0\) 附近的格子间距。BF16 尾数 7 位，在 \([1,2)\) 这个量级里，相邻可表示数间隔 \(2^{-7}=0.0078125\)（python3 验算）。四舍五入规则下，偏离不足半格（\(0.0039\)）的数会被吸回 \(1.0\)。而更新量 \(0.001<0.0039\)，所以 \(1.0-0.001=0.999\) 在 BF16 里落回格子 \(1.0\)——这一步更新被舍入整个吞掉，参数原地不动（python3 模拟验证：把 \(0.999\) 舍入到 BF16 得 \(1.0\)）。结论：BF16 里小更新会被「格子缝」吃掉。这正是 7.3 节「必须用 FP32 主权重」的直接原因。

7.2 上溢与下溢：log-sum-exp 技巧

softmax 把模型输出层的一串 logits \(\mathbf{z}\in\mathbb{R}^{V}\)（\(V\) 是词表大小）变成概率分布：

\[ \operatorname{softmax}(z_{i})=\frac{e^{z_{i}}}{\sum_{j=1}^{V}e^{z_{j}}}. \tag{7.2} \]

数学上它永远良定义。但上机算一次，事故立刻发生：

例 7.2 · 动手算

题目　某一步，输出层对三个候选 token 的 logits 为 \(\mathbf{z}=(1000,\,1001,\,1002)\)。直接按式 (7.2) 计算 softmax，看看计算机里会发生什么。

解　需要先算 \(e^{1000}\)。查边界：双精度浮点（FP64）最大约 \(1.8\times10^{308}\)，而 \(e^{710}\) 就已越界；FP32 更早，\(e^{88.7}\) 左右就溢出（python3 验算：\(\ln(3.4\times10^{38})\approx 88.72\)）。所以在计算机里，\(e^{1000}\) 不是一个「很大的数」，而是直接变成 inf（python3 里 math.exp(1000) 抛 OverflowError）。接下来 inf 除以 inf——式 (7.2) 的分子分母都是 inf——结果是 NaN（not a number，「不是数」）。三个 token 的概率全是 NaN，loss 是 NaN，反向传播把 NaN 乘进每一条梯度，全部参数当场中毒。这就是一次最典型的「训练炸了」，而元凶只是一个指数函数。

直觉 · 先建立感觉

log-sum-exp = 先把所有人的成绩都减去最高分，再排名。 softmax 的本质是一次「按指数成绩排名」：\(e^{z_i}\) 越大，分到的概率越大。排名只关心相对差距——全班每人同时减 100 分，名次不变。那就干脆把每个 logit 都减去最高分 \(m=\max_j z_j\)：第一名变成 0 分，\(e^0=1\)，安全；其他人变成负分，\(e^{z_j-m}\le 1\)，也安全。名次（概率分布）分毫不变，数值上却再也不可能算爆。这就是 log-sum-exp 技巧的全部内容。

推导 · 一步步来

要把直觉框落成公式，只需验证「同时减 \(m\) 不改变 softmax 的结果」。分三步，每步一句理由。 第一步（给分子分母同乘 \(e^{-m}\)）：分数的分子分母同乘一个非零数，值不变（小学分数性质）。取 \(m=\max_j z_j\)， \[ \operatorname{softmax}(z_{i})=\frac{e^{z_{i}}}{\sum_{j}e^{z_{j}}}=\frac{e^{z_{i}}\cdot e^{-m}}{\sum_{j}\bigl(e^{z_{j}}\cdot e^{-m}\bigr)}. \] 为什么偏偏选最大值当 \(m\)？因为它把最大的指数项压到 \(e^0=1\)，其余只会更小——选别的常数也对，但选最大值最保险。 第二步（用指数律合并）：由 \(e^{a}\cdot e^{b}=e^{a+b}\)，有 \(e^{z_i}\cdot e^{-m}=e^{z_i-m}\)。于是 \[ \operatorname{softmax}(z_{i})=\frac{e^{z_{i}-m}}{\sum_{j}e^{z_{j}-m}}. \tag{7.3} \] 第三步（检查数值安全性）：平移后每个指数的自变量 \(z_j-m\le 0\)（因为 \(m\) 是最大值），所以每一项都满足 \(0<e^{z_j-m}\le 1\)，最大的一项恰为 \(e^0=1\)。指数不会上溢；分母至少是 1（最大值那一项贡献的），不会下溢成 0。数学上与式 (7.2) 严格相等，数值上永远安全。证毕。

现在用式 (7.3) 把例 7.2 重算一遍。\(m=1002\)，平移后的 logits 为 \((1000-1002,\,1001-1002,\,1002-1002)=(-2,\,-1,\,0)\)。逐个算指数：\(e^{-2}\approx 0.1353\)，\(e^{-1}\approx 0.3679\)，\(e^{0}=1\)。分母求和：\(0.1353+0.3679+1=1.5032\)。于是

\[ \operatorname{softmax}(\mathbf{z})\approx\left(\frac{0.1353}{1.5032},\ \frac{0.3679}{1.5032},\ \frac{1}{1.5032}\right)=(0.0900,\ 0.2447,\ 0.6652). \] （python3 验算：\(0.090031,\ 0.244728,\ 0.665241\)。）同一组 logits，加一个减法，从 NaN 救回一个完全正常的分布。

训练时还可以更进一步。交叉熵损失需要的是 \(\log p(y)\)，如果「先算 softmax 再取 log」，概率极小时又会下溢。把两步合并成一条稳定版：对式 (7.3) 取对数，对数把除法变减法（\(\log\frac{a}{b}=\log a-\log b\)），得

\[ \log p(y)=z_{y}-m-\log\Bigl(\sum_{j}e^{\,z_{j}-m}\Bigr). \tag{7.4} \]

式 (7.4) 全程不出现单独的 \(e^{z}\)，也没有「先除出小概率再取对数」，同时防住上溢和下溢。所有主流框架的 cross_entropy 算子内部就是这个实现——自己手写「softmax 后接 log」，等于主动绕开保护。

下溢是反方向的事故：\(e^{-1000}\) 直接变 0，多个 0 相乘还是 0，再取 \(\log\) 就是 \(-\infty\)。推理时对长序列算「整句概率」，必须改成对数概率相加，不能把概率连乘。
检查点 ✓

你现在应该能：（1）说出浮点数三部分（符号/指数/尾数）各自管什么；（2）不看表说出「FP16 精但窄、BF16 糙但宽」及其原因；（3）解释 \(e^{1000}\) 在计算机里为什么变成 NaN 而不是「一个很大的数」；（4）独立推出式 (7.3) 并说出选 \(m=\max\) 的理由；（5）手算一组小 logits 的稳定 softmax。

7.3 混合精度训练与损失缩放

直觉 · 先建立感觉

混合精度 = 「草稿纸 + 正式账本」的分工（这是类比）。演算在草稿纸（BF16）上飞快进行，糙点无妨；每步小更新记进正式账本（FP32 主权重），累积分文不差；梯度小到看不见就配放大镜——损失缩放先放大 \(S\) 倍、用完缩回。这个类比省掉了什么：真实舍入发生在每次运算而非只在记账时，格式转换由框架自动完成。

现代 LLM 预训练的标准姿势是混合精度（mixed precision），三条规矩：

（一）前向与反向的计算用 BF16：矩阵乘法吃满 GPU Tensor Core 的吞吐，速度翻倍、显存减半；

（二）另存一份 FP32 主权重（master weights）：优化器读到 BF16 梯度后，在 FP32 主权重上执行第五章式 (5.11) 的更新，更新完再舍回 BF16 供下一步前向使用。为什么必须这样？例 7.1 刚算过：Adam 单步更新量常是权重的 \(10^{-3}\) 量级，而 BF16 在 \(1.0\) 附近的格子间距就有 \(0.0078\)——直接在 BF16 权重上更新，小更新被舍入整个吞掉，参数原地不动，模型「假装在训练」。FP32 的相对精度是 \(6\times10^{-8}\)，比单步更新小几个数量级，吞不掉；

（三）优化器状态（\(\hat m\)、\(\hat v\)）也用 FP32：这两个滑动平均是长期累加量，对精度最敏感。

如果用的是 FP16 而不是 BF16（旧卡、部分推理芯片），还要多处理一件事：下溢。FP16 最小正规数约 \(6.1\times10^{-5}\)，最小次正规数约 \(6\times10^{-8}\)，而深度网络里很多梯度分量在 \(10^{-6}\) 甚至 \(10^{-8}\) 量级——存进 FP16 直接被抹成 0，这些参数从此收不到训练信号。解法是损失缩放（loss scaling）：前向算完损失后，先乘一个大常数 \(S\)（如 \(2^{10}=1024\)）再反向，

\[ \mathcal{L}_{\mathrm{scaled}}=S\cdot\mathcal{L}\;\;\Rightarrow\;\;\nabla\mathcal{L}_{\mathrm{scaled}}=S\cdot\nabla\mathcal{L},\qquad \text{更新前再除以 }S\text{ 还原}. \tag{7.5} \]

为什么梯度恰好放大 \(S\) 倍？链式法则（第二章）：损失整体乘 \(S\)，它对所有参数的导数也整体乘 \(S\)——放大倍率沿链相乘，\(S\) 是链上的第一环。效果用数字看：真值 \(10^{-8}\) 的梯度在 FP16 里下溢成 0；乘 \(S=1024\) 后变成 \(1.024\times10^{-5}\)，落在 FP16 可表示范围内，活下来了（python3 验算：\(10^{-8}\times1024=1.024\times10^{-5}\)）。更新前把梯度除以 \(S\) 还原，数学上与未缩放完全等价。BF16 的指数位与 FP32 相同、范围足够低处，通常不需要这一步——这是 BF16 胜出的又一原因。

与混合精度常捆绑出场的还有梯度累积（gradient accumulation）：逻辑大 batch 切成 \(k\) 个 micro-batch，逐个前向反向、梯度累加，攒满 \(k\) 步才更新一次（记号同第二章式 (2.16)，全书用 \(k\) 表累积步数）。一个数学细节必须钉死：累加得到的是「和」，而 SGD 的无偏估计（第五章式 (5.6)）是「均值」——所以要么每个 micro-batch 的 loss 先除以 \(k\)，要么更新前把累积梯度除以 \(k\)。漏掉这一步，等效于把学习率偷偷放大 \(k\) 倍（见 7.7 常见坑）。

例 7.3 · 动手算（零钱要存进账本才攒得起来）

题目　某参数值为 \(256.0\)，每步更新量 \(+0.5\)，共 100 步。方案一：直接在 BF16 权重上逐步更新；方案二：在 FP32 主权重上累积、最后舍回 BF16。两种方案最终各是多少？

解　先定格子。\(256=2^{8}\)，在 \([256,512)\) 这个量级里，BF16（7 位尾数）的格子间距为 \(2^{8-7}=2\)，半格为 \(1\)（python3 验算）。方案一：每步算 \(256+0.5=256.5\)，它离格子 \(256\) 的距离是 \(0.5\)，不足半格 \(1\)，四舍五入被吸回 \(256\)——每步都被吞，100 步后仍是 \(256.0\)（python3 逐步舍入模拟验证）。方案二：FP32 在该量级的格子间距为 \(2^{8-23}\approx3.05\times10^{-5}\)，\(0.5\) 远大于它，一步也吞不掉；100 步累积得 \(256+100\times0.5=306.0\)，舍回 BF16：\(306=153\times2\) 恰好落在格子上，精确表示（python3 验算）。结论：单步 \(0.5\) 会被 BF16 的格子缝吃掉，但 100 步攒出的 \(+50\) 谁也吃不了——FP32 主权重就是把「零钱」攒成「整钞」的那本账。

7.4 梯度裁剪

直觉 · 先建立感觉

梯度裁剪 = 给这一步更新装上「限速器」。即使学习率设得正确，个别 batch（异常样本、罕见模式、训练早期）也会让梯度范数突然冲大几十倍——一步坏更新足以把参数推飞。裁剪的规则很朴素：更新前先量一下这步梯度的总长度，没超限速就照常走；超了，就整体等比缩小到限速值，方向不变。注意是「整体缩」而不是「每个坐标各自截断」——等比缩小保持方向，逐坐标截断会把方向掰弯。

形式化：把所有参数的梯度拼成一个长向量 \(\mathbf{g}\in\mathbb{R}^{d}\)，算它的全局范数并按阈值 \(\tau\) 缩放：

\[ \lVert\mathbf{g}\rVert=\sqrt{\sum_{i=1}^{d}g_{i}^{2}},\qquad \mathbf{g}\leftarrow\mathbf{g}\cdot\min\!\left(1,\;\frac{\tau}{\lVert\mathbf{g}\rVert}\right). \tag{7.6} \]

读一下这个 \(\min\)：若 \(\lVert\mathbf{g}\rVert\le\tau\)，则 \(\tau/\lVert\mathbf{g}\rVert\ge 1\)，取 \(\min\) 后得 1——不动；若 \(\lVert\mathbf{g}\rVert>\tau\)，取到 \(\tau/\lVert\mathbf{g}\rVert<1\)——整体缩小，缩完范数恰好等于 \(\tau\)。LLM 训练惯例取 \(\tau=1.0\)，几乎无一例外。

例 7.4 · 动手算

题目　某一步全部梯度拼成向量 \(\mathbf{g}=(3,4)\)（示意用的小例子），阈值 \(\tau=2\)。求裁剪后的梯度与它的范数。

解　先量长度：\(\lVert\mathbf{g}\rVert=\sqrt{3^2+4^2}=\sqrt{25}=5\)（勾股数）。\(5>2\)，触发裁剪。缩放因子 \(\tau/\lVert\mathbf{g}\rVert=2/5=0.4\)。逐分量乘 0.4：\(\mathbf{g}'=(3\times0.4,\ 4\times0.4)=(1.2,\ 1.6)\)。验长度：\(\sqrt{1.2^2+1.6^2}=\sqrt{1.44+2.56}=\sqrt{4}=2\)，恰好压在限速上 ✓。验方向：原方向的单位向量是 \((3/5,4/5)=(0.6,0.8)\)，新梯度 \(=2\times(0.6,0.8)\)——方向没动，只有步长被按住（python3 验算一致）。

什么时候能看到它干活？训练日志里的 grad norm 平时稳定在个位数，某一步突然跳到几十几百——裁剪把它压回 1.0 量级，这一步更新「不痛不痒」，训练继续。若尖峰偶尔出现，裁剪就够；若持续出现，那就是 7.5 节的排查问题了。

检查点 ✓

你现在应该能：（1）说出混合精度三条规矩（BF16 计算 / FP32 主权重 / FP32 优化器状态）及各自理由；（2）用「格子间距吞掉小更新」解释为什么必须有主权重；（3）写出损失缩放的放大—还原流程，并用链式法则解释梯度为何恰好放大 \(S\) 倍；（4）说出梯度累积忘除 \(k\) 等效于 lr 放大 \(k\) 倍；（5）手算一次全局范数裁剪，并说明为什么不能逐坐标截断。

7.5 训练「会炸」的排查清单

直觉 · 先建立感觉

排查清单 = 急诊分诊台（这是类比）。NaN 像发烧：症状相同，病因各异——lr 过大、指数上溢、\(\log 0\)、除零、坏数据，对因下药，乱投医越治越糟；loss spike 像高烧自退，用回滚、降速、剔数据三板斧。这个类比省掉了什么：真实训练里几种病因会同时出现、互相掩盖，清单是理想决策树，实际要边试边查。

loss 变成 NaN 时，不要慌，按这五个来源逐一排除（每一行都对应本章已讲过的机理）：

来源机理对策
① 学习率过大违反第五章式 (5.4) 型稳定条件，参数震荡放大直至数值溢出降峰值 lr；加长 warmup；检查调度配置的单位是否写错（步数 vs token 数）
② 指数上溢softmax / 注意力分数未减最大值，\(e^{z}\) 变 inf（例 7.2）用框架的 log_softmax / 融合交叉熵算子；自实现 kernel 必须做式 (7.3) 的平移
③ \(\log 0\)概率下溢成 0 后取对数得 \(-\infty\)，再传播成 NaN用式 (7.4) 的合并实现；实在绕不开处加 \(\varepsilon\)，如 \(\log(x+10^{-9})\)
④ 除零归一化的分母为 0（空序列、方差为 0 的层、0/0）分母加 \(\varepsilon\)；检查数据里是否有全零 / 定值样本；Adam 的 \(\varepsilon\) 同理
⑤ 坏数据语料中混入 NaN/inf 或极端值样本，前向第一行就产毒数据侧过滤；训练侧检测到非有限 loss 时跳过该 batch 并记录

比 NaN 更常见的是 loss spike（尖峰）：损失曲线突然上冲，再回落（或不回落）。标准处置流程分三步：回滚——回到尖峰之前的 checkpoint；降速——临时降低学习率或延长 warmup 再续训；剔数据——若能定位到具体数据批次，剔除后重放。主流 LLM 训练框架内建了尖峰自动跳过与回滚逻辑，本质都是本章工具的组合：用梯度裁剪止血、用调度降速、用检查点回滚。

例 7.5 · 动手算（lr 过大是怎么一步步炸的）

题目　最小化一维二次损失 \(L(x)=2x^{2}\)（梯度 \(L'(x)=4x\)，曲率 \(\lambda=4\)），从 \(x_{0}=1\) 出发做梯度下降 \(x\leftarrow x-\eta\cdot4x\)。取 \(\eta=0.6\)，手算 4 步，观察参数与损失的变化。

解　把每步更新合并：\(x\leftarrow(1-4\eta)x\)。代入 \(\eta=0.6\)：\(1-4\times0.6=-1.4\)，即每步乘以 \(-1.4\)——绝对值大于 1，还带负号。逐步算：\(1\to-1.4\to1.96\to-2.744\to3.8416\)（python3 验算）。参数左右横跳、越跳越远；损失 \(2x^{2}\) 跟着一路上冲：\(2\to3.92\to7.68\to15.06\)。照此下去就是溢出、inf、NaN。对照第五章的稳定条件 \(\eta<2/\lambda_{\max}=2/4=0.5\)：\(\eta=0.6\) 越界，所以发散；若改取 \(\eta=0.4\)，因子为 \(1-1.6=-0.6\)，绝对值小于 1，震荡但收敛（\(1\to-0.6\to0.36\to\cdots\)）；恰好取 \(\eta=0.5\) 时因子为 \(-1\)，原地等幅弹跳、永不收敛（python3 验算三种因子）。这就是排查清单来源①「学习率过大」的完整机理：不是玄学，是每步放大因子的绝对值过了 1。

7.6 条件数：地形越扁，下山越晃

直觉 · 先建立感觉

条件数 = 地形有多「扁长」；越扁越长，下山越容易来回震荡。回忆第五章的峡谷：横截面方向坡度陡，沿谷底方向坡度缓。蒙眼下山的人在这种地形里很为难——步子按陡坡的标准定（否则横向跨过谷底撞墙），在缓坡方向上就只能一小步一小步蹭；横向上还稍不留神就左右弹跳。地形越扁长（陡坡与缓坡的曲率差距越大），这个矛盾越尖锐，GD 的之字形弹跳越厉害。这个「扁长程度」的度量，就是条件数。

形式化：对对称正定矩阵 \(\mathbf{A}\in\mathbb{R}^{d\times d}\)（比如二次型问题的 Hessian，即损失面的曲率矩阵），定义条件数

\[ \kappa(\mathbf{A})=\frac{\lambda_{\max}(\mathbf{A})}{\lambda_{\min}(\mathbf{A})}, \tag{7.7} \]

即「最陡方向的曲率 ÷ 最平方向的曲率」。为什么它决定 GD 的表现？把第五章的两条结论拼起来：GD 稳定要求 \(\eta<2/\lambda_{\max}\)——学习率被最陡方向卡住；而在最平方向上，每步只走相对进度 \(\eta\lambda_{\min}\)。两个方向的进度比正好是 \(\lambda_{\max}/\lambda_{\min}=\kappa\)：\(\kappa=100\) 意味着「把陡方向按住的 lr」在平方向上慢 100 倍。几何上，等高线是长宽比 \(\sqrt{\kappa}\) 的椭圆族——正是第五章的峡谷地形。

这给了 Adam 一层新的解读：式 (5.11) 里的 \(1/\sqrt{\hat{\mathbf{v}}}\) 按坐标逐一缩放步长，近似把各坐标有效曲率拉平，相当于把峡谷「捏圆」——是工程上对高条件数问题的实用回应（真正的二阶方法要求 \(\mathbf{A}^{-1}\)，在千亿参数上根本存不下也算不动）。

易混点：条件数是问题的属性（地形多扁），学习率是算法的旋钮。lr 治不了病态，只能保证不炸；治病态要靠自适应方法（Adam 的逐坐标缩放）或预条件。
例 7.6 · 动手算（\(\kappa=16\) 的峡谷有多难走）

题目　某二次型问题的 Hessian 为对角阵 \(\mathbf{A}=\mathrm{diag}(4,\ 0.25)\)。求条件数 \(\kappa(\mathbf{A})\) 与等高线椭圆的长宽比；取稳定上界附近的学习率 \(\eta=0.4\)，分别算陡、平两个方向上 10 步后误差还剩多少。

解　对角阵的特征值就是对角元：\(\lambda_{\max}=4\)，\(\lambda_{\min}=0.25\)。代入式 (7.7)：\(\kappa=4/0.25=16\)，长宽比 \(\sqrt{\kappa}=4\)——等高线是 4:1 的扁椭圆。学习率上界 \(2/\lambda_{\max}=0.5\)，取 \(\eta=0.4\) 合法。GD 在每个特征方向上，误差每步乘以 \(1-\eta\lambda\)：陡方向为 \(1-0.4\times4=-0.6\)，每步收缩到 \(0.6\)；平方向为 \(1-0.4\times0.25=0.9\)，每步只收缩到 \(0.9\)。10 步后：陡方向误差剩 \(0.6^{10}\approx0.006\)（不足百分之一），平方向还剩 \(0.9^{10}\approx0.349\)（三成多没消掉，python3 验算）。同一个学习率，陡方向早已到位，平方向才走了约三分之二——学习率被最陡方向卡住，最平方向只能小步蹭，这就是 \(\kappa=16\) 的代价，也正是 Adam 逐坐标缩放想要「捏圆」的东西。

7.7 常见坑

常见坑

在低精度里直接算 softmax。手写 kernel 或推理代码时直接在 FP16/BF16 里算 \(e^{z}\)：FP16 下 logits 超过约 11（\(\ln 65504\approx 11.09\)，python3 验算）就溢出成 inf；BF16 虽范围宽，但 7 位尾数让相邻概率的相对误差达千分之几，分布尾部直接失真。改法：softmax、log_softmax、交叉熵、LayerNorm 的统计量，一律转成 FP32 计算后再舍回——主流 kernel（FlashAttention 的在线 softmax）内部正是这么做的。

常见坑

梯度累积后忘记等比缩放。两种翻法：micro-batch 的 loss 没除以累积步数 \(k\)，梯度实际是均值的 \(k\) 倍，等效学习率偷偷放大 \(k\) 倍，轻则 loss 偏高、重则直接炸；或者改了累积步数（有效 batch 变了）却沿用旧 lr。改法：loss 除以 \(k\) 或更新前梯度除以 \(k\)，二选一并在代码里写死注释；有效 batch（micro-batch × 累积步数 × 数据并行度）变动时，按同一比例调 lr，warmup 步数占比保持不变。

例 7.7 · 动手算（忘除 \(k\) 的代价有多大）

题目　逻辑 batch 切成 \(k=4\) 个 micro-batch，某参数在四个 micro-batch 上的梯度分别为 \(0.2,\,-0.1,\,0.3,\,0.1\)，学习率 \(\eta=0.1\)。正确流程（先求均值）与翻车流程（直接累加不除 \(k\)）各给出多大的更新？

解　正确的无偏估计是均值：\(\bar g=(0.2-0.1+0.3+0.1)/4=0.5/4=0.125\)，更新量 \(\eta\,\bar g=0.1\times0.125=0.0125\)。翻车流程把四个梯度直接累加：\(g_{\mathrm{sum}}=0.5\)，更新量 \(\eta\,g_{\mathrm{sum}}=0.1\times0.5=0.05\)。比较：\(0.05/0.0125=4\)——恰好 \(k\) 倍（python3 验算）。也就是说，忘记除 \(k\) 与「把学习率偷偷改成 \(0.4\)」在数学上无法区分：配置里写着 \(0.1\)，实际生效的是 \(0.4\)。若这个等效学习率越过了稳定红线（例 7.5 刚算过那种 \(\eta=0.5\) 的界线就在眼前），训练便「莫名其妙」地炸了——查学习率配置一切正常，因为问题藏在累积里。改法即本节第二坑：loss 先除以 \(k\)，或更新前梯度除以 \(k\)，二选一写死。

7.8 在 AI 中的位置

本章结论具体 AI 组件 / 机制缺了会怎样
log-sum-exp 平移（式 7.3、7.4）注意力 softmax、输出层分布、交叉熵的每一次计算；FlashAttention 在线 softmax 的数值底座logits 稍大即 inf/NaN，一次前向就毒化全部参数
BF16 范围同 FP32、精度只 7 位尾数（7.1 节表格）LLM 训练默认姿势：前向/反向 BF16 + FP32 主权重 + FP32 优化器状态纯 FP32 训练显存与算力成本翻 2–3 倍；直接在 BF16 权重上更新则小更新被舍入吞掉（例 7.1）
损失缩放（式 7.5）FP16 混合精度训练（旧卡、部分推理芯片）小梯度下溢成 0，大量参数停止学习，loss 卡住不降
全局范数梯度裁剪（式 7.6）几乎所有 LLM 训练配置里的 grad_clip=1.0个别坏 batch 的一步大更新把训练推飞，loss spike 或 NaN
条件数与病态（式 7.7）解释 Adam 的 \(1/\sqrt{\hat v}\) 为何有效；优化器选择的理论线索把病态造成的震荡误当发散，乱降 lr 拖慢训练
下溢与对数概率（7.2 节批注）推理时长序列用 logprob 累加而非概率连乘；KV cache 量化（INT8/FP8）的误差来源正是低精度舍入噪声（量化章展开）概率连乘下溢成 0，长文本似然计算报废；量化误差无估算依据

一句话总结：混合精度（BF16 + FP32 主权重）是 LLM 训练的默认姿势，log-sum-exp 是 softmax / 交叉熵 / FlashAttention 的数值底座，梯度裁剪与排查清单是训练日志的急救包。本章没有一行是纯理论——每一行都对应一次真实发生过的「训练炸了」。

自测题

题 1（稳定 softmax 手算）　对 logits \(\mathbf{z}=(2,1,0)\)，用 log-sum-exp 技巧手算 softmax（保留 4 位小数），并说明：如果 logits 同时加上 100，答案会不会变？

看答案

取 \(m=\max=2\)，平移后 logits 为 \((0,-1,-2)\)。指数：\(e^0=1\)，\(e^{-1}\approx0.3679\)，\(e^{-2}\approx0.1353\)；分母 \(1+0.3679+0.1353=1.5032\)。softmax \(=(1/1.5032,\ 0.3679/1.5032,\ 0.1353/1.5032)\approx(0.6652,\ 0.2447,\ 0.0900)\)（python3 验算：0.665241、0.244728、0.090031）。logits 同时加 100 不变：式 (7.3) 的推导对任意平移严格成立（这正是「减最高分再排名」的依据）；数值上加 100 后直算式 (7.2) 可能在低精度下溢出，而稳定版照样安全。

题 2（梯度裁剪）　某步梯度拼成 \(\mathbf{g}=(6,8)\)，阈值 \(\tau=5\)。求裁剪后的梯度，验证其范数与方向。

看答案

范数 \(\sqrt{6^2+8^2}=\sqrt{100}=10>5\)，触发裁剪；因子 \(\tau/\lVert\mathbf{g}\rVert=0.5\)；裁剪后 \(\mathbf{g}'=(3,4)\)。新范数 \(\sqrt{9+16}=5=\tau\) ✓；方向单位向量仍是 \((0.6,0.8)\)，未变 ✓（python3 验算一致）。

题 3（损失缩放救命）　某梯度分量真值为 \(10^{-8}\)。FP16 的最小次正规数约 \(6\times10^{-8}\)。（a）不缩放直接存 FP16，这个梯度会怎样？（b）取 \(S=1024\) 做损失缩放后，它变成多少？能否表示？（c）为什么 BF16 训练通常不需要这一步？

看答案

（a）\(10^{-8}<6\times10^{-8}\)，低于 FP16 能表示的最小正数，下溢成 0——该参数这一步收不到训练信号。（b）\(10^{-8}\times 1024=1.024\times10^{-5}\)（python3 验算），大于最小次正规数，可表示；更新前再除以 1024 还原真值。（c）BF16 指数位与 FP32 相同（8 位），可表示范围直到约 \(10^{-38}\) 量级的小数，常规梯度不会下溢，故一般免做损失缩放——这正是「范围比精度更要紧」的又一例证。
